# 命令分析、权限与沙箱整体改造计划

日期：2026-09-20  
状态：已实施可落地部分；P01/P04/P05 的完整 workspace 后端受宿主 user namespace 策略阻塞，按契约 fail closed。  
范围：DAgent 的 bash 执行、权限判断、执行边界、审批交互及相关会话记录。  
入口：按 P01 → P10 的依赖顺序实施；不得先删除现有审批条件，再补执行隔离。

## 1. 问题与目标

当前对 `cd`、`2>/dev/null` 的修复解决了具体误判，但不能覆盖 Shell 的组合语义。
根本问题是 `Analysis::has_opaque` 混合了语法错误、动态行为、写入影响与未知语法，
而 `workspace` 权限把该标记直接用作自动执行的否决条件。

本次目标是建立稳定的职责分工：

1. 命令分析描述语法、已知影响和不确定部分，不替代操作系统执行权限。
2. 权限策略依据用户模式、明确授权、命令事实和后端实际能力决定运行范围。
3. 沙箱对整条命令及其所有子进程落实目录、网络、本地通信等访问边界。
4. 审批围绕需要增加的权限展开，给出原因、目标和有效期。
5. 通过语法类别、权限类别和真实运行覆盖验收，不再逐条补输入字符串。

成功后的主要体验：在 `workspace` 模式及合格沙箱下，正常的管道、重定向、变量、循环、
子 Shell 和本地脚本不因“无法完全静态理解”而反复审批；超出授权范围的操作仍受限制。

12. 作为开发者，我希望 unrestricted 保持已有显式授权含义，不因本次重构产生隐藏的模式变化。

## 4. 权限契约

### 4.1 模式

以下为目标行为；现有高危硬拦继续优先，不能解释为承诺静态识别任意脚本中的全部危险行为。

| 场景 | ask | workspace | unrestricted |
| --- | --- | --- | --- |
| 明确只读，执行边界满足 | 自动，以只读配置运行 | 自动，以只读配置运行 | 按现有全访问语义运行 |
| 普通工程写入 | 审批后在所授权范围执行 | 自动，在工程可写范围执行 | 自动 |
| 语法有效但行为动态的本地命令 | 审批 | 合格工作区沙箱内自动执行 | 自动 |
| 明确申请额外目录 | 审批具体范围 | 审批具体范围 | 自动 |
| 需要未获准的网络目标 | 审批具体目标 | 审批具体目标 | 按现有全访问语义执行 |
| 敏感读取、受保护写入 | 单次明确审批或按用户拒绝规则阻止 | 同左 | 保持现有模式契约 |
| 无法建立要求的沙箱 | 不运行；报告能力不足 | 不运行；保留保守路径 | 明确使用全访问，不伪装成沙箱 |
| Bash 语法错误 | 不执行，返回解析位置 | 同左 | 同左 |

“语法错误不执行”用于阻止 Bash 在较晚出现语法错误之前先执行前面的完整语句。
“分析不完整但语法有效”必须与它分开；解析器不支持的合法语法不能假冒已确认语法错误。

`read_only` / `plan` 继续高于三档模式：已知写入拒绝；动态程序仅在完整只读边界得到验证后
才允许以只读配置执行，否则保守拒绝。它们不通过审批获得工程写权限；用户应显式退出对应模式。
只读运行可以使用私有临时空间，但不能把它当作工程目录或共享临时目录的可写授权。

### 4.2 基础边界

- 工程根以当前工具实际使用的 workspace 根为准，不把 git 根、展示路径和启动 cwd 混为一谈。
- 普通源码及构建输出可按 workspace 授权写入。可写工程范围意味着普通文件也可以被删除；
  沙箱本身不提供“理解用户意图”或自动回滚能力。
- 模型凭据、代理权限配置、提示词、会话数据库、日志和授权存储属于代理控制数据。
  即使它们位于工程 `home/` 内，普通 bash 也不能因此得到默认敏感读取或自修改权限。
- `.ssh`、`.gnupg`、模型凭据等敏感读取受独立限制；受保护控制数据不能被命令前缀或宽泛目录授权间接放行。
- `.git` 的普通状态读取应能工作；写入 git 元数据需要明确授权。不要把源码可写自动等同于
  可修改 hooks、配置或历史。获准的 git 操作只能获得必要范围，不能默认获得整个宿主访问。
- 标准工具链、共享库、系统证书等可按需要读取。能力设计必须兼顾真实构建，不能简单把工程外所有读取封死。
- 网络默认关闭；如开放域名授权，必须有实际强制经过的受控出口，不能只设置可绕过的代理环境变量。
- Unix socket、代理进程通信、继承文件描述符和进程间控制属于边界的一部分，不能把“禁 TCP”写成“无外部影响”。
- 临时空间独立；通过实际隔离与可写策略限制访问。只设置 `TMPDIR` 不等于隔离 `/tmp`。
- 路径别名、软链接、重命名和执行前后的路径变化，由真实文件系统策略兜底；字符串前缀检查不能承担最终授权。

## 5. 命令分析设计

### 5.1 分析结果

用结构化结果替代单一否决位，最少包括：

| 信息 | 含义 |
| --- | --- |
| 语法状态与位置 | 有效、语法错误、解析器不支持/不完整；保留对应源码范围 |
| 命令结构 | 简单命令、组合关系、嵌套关系，及每段原文 |
| 参数确定性 | 字面量、可静态还原、运行时展开；不将未求值表达式冒充实际 argv |
| 工作目录状态 | 已知绝对目录或未知状态；记录影响后续路径的操作 |
| 已知影响 | 读取、写入、网络请求或需特殊授权的操作，以及能确定的目标 |
| 动态影响 | 存在运行时展开或不透明程序；未知不等于恶意，也不等于只读 |
| 风险证据 | 命中哪项规则、哪段命令，供策略与 UI 使用 |

分析时禁止执行命令替换、source、脚本、插件或用户函数来“求出结果”。
可做字面量解码和有限的确定性传播，不实现一套 Bash 解释器。

### 5.2 按语法类别处理

| 类别 | 必须覆盖的语义 | 不确定时的处理 |
| --- | --- | --- |
| 简单命令 | 引号、转义、选项边界、参数、路径形式的可执行文件 | 不认识程序时标记动态，不因名称不在名单而判恶意 |
| `;`、`&&`、`||` | 分别保留顺序与条件关系，合并可能产生的影响 | 按所有可能执行分支判断权限，不假定前段一定成功 |
| 管道与 `\|&` | 全部进程、重定向和嵌套命令均参与分析 | 不只分析第一段或最后一段 |
| 重定向 | 输入、输出、追加、覆盖、描述符复制/关闭、here-document、here-string | 保留展开与目标未知性，不把复制描述符误判为磁盘写入 |
| 输出到 `/dev/null` | 原有常见形式与引号形式回归覆盖 | 只是无持久写入的目标，不豁免同一命令中的其他操作 |
| `cd` | 相对路径、子目录、多次切换、条件分支与子 Shell 作用域 | 失去确定性后标记 cwd 未知，不能反复从初始根解析相对路径 |
| 变量与环境 | 普通参数变量和影响执行行为的 PATH、BASH_ENV、LD_PRELOAD 等分开记录 | 不确定参数留给沙箱；环境不能成为读取控制数据或注入凭据的通道 |
| glob、花括号展开 | 与普通字面量区分，记录可能改变目标或选项的展开 | 不把未经展开的参数直接送进“已知只读”证明 |
| 命令/进程替换 | 递归收集可见命令及数据流位置 | 不在分析阶段执行，不遗漏其写入或联网 |
| 子 Shell、分组、循环、条件、函数 | 保留嵌套结构与可能副作用 | 有效语法在合格 workspace 沙箱内可运行 |
| `env`、`command`、`timeout` 等包装 | 可确定时识别实际执行目标与包装选项 | 不认识的包装仍是动态执行，不放宽边界 |
| `bash -c`、解释器、本地脚本、构建系统 | 已知字面量 Shell 可以有限递归分析；外部程序不能靠名字证明只读 | 权限由模式与执行范围约束 |

`find -exec`、git 外部辅助程序、包管理脚本等不能因为外层命令常见就获得“只读”标签。
高风险操作规则保留，作为用户意图控制的一层；不得宣称它能覆盖任意程序的全部行为。

## 6. 执行边界与后端选择

### 6.1 能力报告

不能继续只用 `landlock_abi > 0 && seccomp` 表示“沙箱可用”。后端应报告：

- 实际后端、版本与当前运行环境是否允许启动。
- 文件读取、写入、截断、重命名、相关元数据/设备操作的可约束范围。
- 是否支持工程内的受保护子路径、敏感读取、私有临时空间。
- 网络、本地 socket、进程间控制和继承句柄的限制能力。
- 子进程继承、取消、超时与清理能力。
- 哪个运行配置满足要求，哪个不满足，以及明确的缺失原因。

不支持的能力必须显示为缺失，不能在构建时头文件未定义或内核 ABI 不足时静默去掉限制，
随后仍报告“完整只读”或“完整工作区沙箱”。

### 6.2 选型与落地决策

优先复用成熟系统组件，保持 C++ 核心通过现有 exec 边界调用后端：

1. P01 首先检查本机 bubblewrap 网络 namespace 的失败原因，并评估固定版本 sandbox-runtime 的
   CLI 接入、许可证、依赖、启动成本、取消行为和实际能力；不默认把 Node 库直接嵌入 C++。
2. 若成熟后端在本机可运行且满足要求，首版只实现该后端适配，不同时维护两套等价策略生成器。
3. 若依赖本机没有的系统授权，记录具体部署条件；不得自行修改 sysctl、AppArmor、容器权限或启动特权服务。
4. 原 Landlock + seccomp 后端保留为兼容路径。只有其扩展实现也通过同一能力验收，才可启用
   任意动态命令的 workspace 自动运行。不能以“兼容”为理由降低保护并维持相同能力标签。
5. 两条路径都无法满足要求时，保守行为继续可用，P04/P05 的自动化目标标记为受环境阻塞，
   不能宣布整体完成。后端决策与证据写回本计划，再进入 P04 的实现。

Landlock 的父目录放行不能在同一个规则集中用一条“deny 子目录”撤销；如采用多层规则或其他
机制保护工程内控制文件，必须验证新建目录、重命名、链接与路径变化，不使用静态枚举伪装强制排除。
是否需要额外进程/IPC 隔离和系统调用限制，由能力清单与实际操作覆盖确定。

### 6.3 最小执行授权

`Grant` 应携带明确的运行范围：执行配置、额外可读/可写目录、获准网络目标及有效期，
而不只是 `sandbox` 枚举加 `allow_network` 布尔值。
权限在 exec 前落实，覆盖整个进程树；后端准备失败时不得回退运行原始命令。
模型服务连接继续由宿主 Agent 管理，不把模型 API 凭据复制到命令环境中以解决网络问题。

## 7. 审批、配置与会话

### 7.1 审批请求

请求至少包含：调用标识、完整原命令、工作目录、当前模式、分析摘要、所请求权限、
具体目标、理由、有效期选项，以及是否已有部分执行。
摘要截断只用于显示；判断、授权绑定、记录与复用必须使用完整数据。

UI 复用已有审批对话框与 Panel，不增加 TUI 框架原语：

- 展示“读取额外目录 / 写入额外目录 / 访问网络目标 / 执行不确定命令”等具体原因。
- 支持单次允许、会话允许、拒绝、拒绝附说明；敏感控制数据仅提供单次授权。
- 增加 `/permissions` 会话授权列表，可查看范围并撤销；不要求用户手工编辑配置。
- 区分“授权后仍在沙箱中运行”和“用户显式选择 unrestricted”。
- 不自动把一次目录或联网批准扩大为全访问；不把 unknown 目标自动变成 `*`。

### 7.2 规则与配置

- 保留 `home/config.json` 当前 `permissions` 字符串；新增沙箱策略使用独立、版本化的配置结构，
  P02 定义字段、默认值与配置覆盖关系，避免直接把现有字段改成不兼容对象。
- 配置、提示词和规则来源继续集中在当前安装根 `home/`，dev 默认位置不变。
- 单次授权绑定该次调用及实际工作目录；会话授权绑定规范化目标、权限类别和有效范围。
- 会话授权仅存于当前会话内存，日志/历史中的记录不等于恢复后的有效授权。
- 用户维护的持久策略由宿主加载；首版不提供一键永久授权或把会话批准自动写为长期规则。
- 原命令前缀授权只保留明确、静态、边界不扩张的兼容行为；动态命令不得仅凭前两个单词复用授权。
- 优先级：只读/plan 与高危硬拦 → 显式拒绝 → 已有具体授权 → 模式默认。
  既有 unrestricted 语义保持；明确拒绝规则与模式切换的展示须一致。
- 撤销对下一次执行生效；不能声称已经撤回运行中进程持有的文件权限。
  用户可通过现有中断操作停止该调用，避免引入不明确的“实时撤销全部权限”承诺。

### 7.3 记录、调度与恢复

- bash prepare 生成一次结构化分析，策略、审批和执行复用；不让不同阶段重新分析出不同授权范围。
- 记录后端、有效执行配置、授权来源、命令分析版本及执行状态；不记录密钥、完整环境变量或敏感文件内容。
- 扩展 Approval、Decision、BashView 与相应序列化；旧记录缺字段时以 unknown 展示，不能补造历史授权。
- 优先在现有 SQLite 事件 payload 中增加版本化可选字段；无需为每个分析节点新增表。
- 只有已知只读且获得只读执行范围的调用可进入只读并行组；动态命令即便运行在只读沙箱也默认串行。
- `tool.started` 之前可区分“未执行”；之后即使退出失败，也应视为可能已有副作用。
- 恢复会话继续遵守既有防重复执行规则；不重放已开始调用，不恢复失效的单次/会话授权。
- MCP 授权保持既有独立流程；本轮不把 bash 沙箱覆盖范围描述成涵盖全部远程 MCP。

## 8. 错误与重试契约

| 状态 | 所需证据 | 行为 |
| --- | --- | --- |
| 分析失败 | 解析位置及错误类别 | 未执行，返回可修改的命令问题 |
| 用户拒绝/取消 | Approver 的明确结果 | 不执行该调用，按现有会话语义继续或结束 |
| 沙箱准备失败 | 后端启动/规则安装错误 | 未执行，不自动回退 full_access |
| 明确访问被拒 | 可归属于本次调用的后端/代理拒绝证据 | 报告目标与当前范围，由用户决定是否补充授权 |
| 普通程序失败 | 退出码、信号或程序输出 | 不自行解释为权限不足 |
| 疑似权限失败 | 只有 stderr 字符串，无法证明来源 | 标明未确认，不自动生成扩大权限的请求 |
| 超时/中断/执行后失败 | 已有 tool.started 或输出 | 保留部分结果、清理进程树，不自动整条重跑 |

Linux 后端未必提供精确的拒绝路径；拿不到时应显示“操作失败，具体被拒目标未知”，
不能编造结构化访问事件。程序自身输出的 Permission denied 不能作为可信的提权指令。

对于复合命令，某个后续操作失败不代表前序操作未发生。文件系统权限变更通常需要新执行；
不得设计成“先试运行，失败后自动扩权重跑”。网络代理若能在建立目标连接之前等待单次批准，
可以恢复该连接请求，但不能借此自动重新执行整个 Shell。

## 10. 验收矩阵与证据

### 10.1 语法覆盖

每类至少包含一个正常用法及一个不同影响的对照，不枚举无限多条字符串。

| 编号 | 类别 | 必需的真实行为 |
| --- | --- | --- |
| A01 | 原始问题 | 原 `ls / head / echo / wc + glob + 2>/dev/null` 命令成功，无审批 |
| A02 | 管道与条件组合 | 多段管道、`&&`、`||`、`;`；后段影响不能被前段只读掩盖 |
| A03 | 重定向 | 普通读入、输出、追加、fd 复制、null、引号路径、多个重定向分别正确处理 |
| A04 | 工作目录 | 原地 cd、子目录、连续 cd、子 Shell cd、条件 cd；后续路径基准正确 |
| A05 | 变量与环境 | 普通变量构造与影响程序装载的环境变量不混为一类；不泄露宿主凭据 |
| A06 | 展开 | glob、花括号、命令替换、进程替换，包括嵌套真实读取和写入 |
| A07 | 控制流 | 循环、条件、函数、分组；只读和有写入的实际效果分别核对 |
| A08 | 外部程序 | 真实构建命令、脚本/解释器、可执行文件路径、包装命令；子进程同样受限 |
| A09 | 异常输入 | 语法错误、解析不完整、多行输入、引号与控制字符；不存在分析执行不一致 |

### 10.2 执行边界覆盖

所有受保护数据使用 `temp/` 下的普通验收材料配置为同类受保护路径，不读取或泄露真实密钥。
外部目录使用工程验证工作区之外、但仍位于项目 `temp/` 下的相邻目录，避免影响用户其他项目。

| 编号 | 边界 | 必需的真实行为 |
| --- | --- | --- |
| B01 | 工作区内外写入 | 内部写入按模式允许；外部写入不获授权不发生 |
| B02 | 控制数据 | workspace 中的受保护子目录仍不可擅自写入；敏感读取被有效阻止 |
| B03 | 路径变化 | 软链接、重命名、路径别名、父目录创建/删除不能越过边界 |
| B04 | 读与写的实际效果 | 写入、追加、截断、删除、改名及后端无法限制的元数据操作均有明确结果 |
| B05 | 网络 | 未授权出口被阻止；授权域名仅经受控通道可用，不能因设置环境变量即获得全网访问 |
| B06 | 本地通信 | 未授权 Unix socket、代理通信、继承 fd 与跨边界进程操作不能形成替代出口 |
| B07 | 临时空间 | 私有临时文件可用；共享临时目录和其他调用的数据不因此可写 |
| B08 | 子进程 | 包装器、脚本和后续派生进程继承限制；超时/取消后没有遗留执行 |
| B09 | 后端不足 | 准备失败、缺少能力、namespace 失败时不执行原始命令，不静默降级 |

若真实网络或本地通信验证需要启动服务，必须使用实际服务程序，明确生命周期并只操作本次创建的实例；
不得创建模拟模型、假服务代码或离线替身来替代边界验证。

### 10.3 权限与生命周期覆盖

- C01：ask / workspace / unrestricted × 已知只读 / 普通写入 / 动态执行 / 额外权限。
- C02：read_only 与 plan 的工程写入限制，包含解释器和子进程。
- C03：单次授权不用于下一次不同调用；会话授权不跨会话，目标变化必须重新判断。
- C04：UI 批准、拒绝、拒绝附说明、Esc、取消、查看授权、撤销，均通过真实 PTY 操作。
- C05：headless 缺少交互授权时明确失败；无需权限的调用仍可成功。
- C06：启动失败与部分执行失败分开；一条组合命令前段完成后，不能因后段拒绝而自动重放。
- C07：恢复旧会话不报错；新授权记录可回放但不自动生效；已开始调用不重复执行。
- C08：只读并行组只包含符合资格的调用；写入和动态命令不因改造错误并行。
- C09：完整命令相同前 100 字符但后段不同，不能共享单次授权或错误归因。

## 11. 范围与迁移限制

本轮不做：跨平台沙箱、全新 Shell 解释器、重写 tree-sitter、训练权限分类模型、
为每条工具调用增加第二次 LLM 审批、自动撤销任意文件改动、远程 MCP 全部容器化、永久授权 UI、
新建特权守护进程、自动修改宿主安全配置、无关 TUI 设计重构。

文件布局保持不变：hpp 仅在 `src/public/`，cpp 仅在 `src/private/`；TUI 框架只修相关缺陷，不扩展公开原语。
保留用户已有修改及 DeepSeek 等模型配置；不得为验收切换、停止或重启用户的模型服务。

迁移采用“新结果接入、旧路径保守运行、能力通过后启用”的顺序；禁止仅删除 `has_opaque` 判断来宣称完成。
回退只能恢复保守审批或停止不能隔离的执行，不能把失败后端的行为等同于 unrestricted。

- [ ] 审批粒度明确，失效授权不复活，无自动提权整条重跑。
- [ ] 必需真实运行矩阵通过；没有新增测试代码或无关实现。
- [ ] 当前设计文档同步真实结果，已知后端限制被准确说明。

## 13. 参考依据

以下资料用于设计取舍，不能替代选定版本与本机环境的实际验收：

- [OpenCode permissions](https://opencode.ai/docs/permissions/)：模式规则、命令匹配及会话授权。
  本机 OpenCode 1.18.31 的 Shell 路径也使用语法解析和权限规则；低审批不能被解释为可静态理解所有脚本。

- [Anthropic sandbox-runtime](https://github.com/anthropics/sandbox-runtime)：可复用的执行边界实现；当前标注研究预览，须固定版本。
- [bubblewrap](https://github.com/containers/bubblewrap)：系统隔离组件；保护程度由调用方构建的具体策略决定。
- [Linux Landlock](https://docs.kernel.org/userspace-api/landlock.html)：ABI、文件访问权限、IPC 及既有限制。
- [现有 exec 设计](../docs/design/exec.md)、[现有 agent 设计](../docs/design/agent.md)：迁移起点，描述当前能力。
