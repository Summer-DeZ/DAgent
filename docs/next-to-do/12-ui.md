# 12 交互界面

> 里程碑：C4 · 位置 `src/*/ui`，库 `dagent_ui` · 依赖 agent、tui、tools（View）

`dagent` 不带子命令时进入的全屏界面。它是 agent 两个对外接口（Sink、Approver）的交互实现，外加输入、快捷键和
显示。**只用冻结的 TUI 原语搭建，不改 `src/*/tui`**；框架里没有的东西（对话渲染、对话框、状态栏）都在这里做。

框架的接入方式见 [tui 设计文档](../design/tui-framework.md) §3「应用接入」。

---

## 1. 职责

**做**：布局与主题；agent 线程和任务队列；把 Event 画成对话；权限对话框；输入、排队、斜杠命令、快捷键；状态栏和
活动行；退出。

**不做**：任何 agent 逻辑。界面只认 `agent::Event`、`agent::Approval`、`tools::View`，只调 `Agent` 的公开方法。

---

## 2. 接口与组成

```cpp
namespace dagent::ui {

struct InteractiveOptions {
    std::string initial_prompt;                   ///< dagent "提示词"：进入后立即发送
    std::optional<std::string> resume_id;
    bool continue_last = false;
    std::optional<std::filesystem::path> theme_file;
};

/// 阻塞到用户退出，返回退出码。
int run_interactive(agent::Setup, const InteractiveOptions&, agent::Interrupts&);

} // namespace dagent::ui
```

| 类 | 文件 | 职责 |
| --- | --- | --- |
| `Shell` | `shell.hpp/.cpp` | 持有 Terminal、Runtime、控件树、Keymap、Agent、agent 线程与任务队列；`run_interactive` 的实现 |
| `Transcript` | `transcript.hpp/.cpp` | Event → Document 块；只在渲染线程上用 |
| `ChatRenderer` | `transcript.cpp` 内部 | `BlockKind::text` 的渲染器：按块的 `meta` 标签选样式和前缀（§6.1） |
| `ApprovalDialog` | `approval.hpp/.cpp` | 权限对话框控件 + 它的模态事件处理器 |
| `PromptInput` | `prompt_input.hpp/.cpp` | 输入框的事件处理器：发送、换行、排队、斜杠命令，其余交给 `tui::InputBoxHandler` |
| `StatusLine` | `status_line.hpp/.cpp` | 状态栏控件 |

## 3. 布局

```
LayerStack
└─ Container(vertical)
   ├─ Scrollback        {flex, 1}     对话
   ├─ Activity          {content}     「思考中 12s」「运行 make test 3s」；空闲时高度 0
   ├─ Notice            {content}     临时提示：重试、警告；5 秒后自动清除
   ├─ Text（排队）       {content}     「排队：…」；没有排队时为空
   ├─ InputBox          {content}     输入
   └─ StatusLine        {fixed, 1}    模型 · 上下文 · 权限模式 · MCP · 会话
浮层：ApprovalDialog（模态，居中）
```

- 主题：`InteractiveOptions::theme_file` 给了就 `ui::load_theme`，否则用框架内置主题；在 `Runtime::on_caps` 回调里按
  终端背景 `pick`，递增 epoch 后设给各控件（ui 模块已有的约定）。主题文件路径来自新配置键 `ui.theme_file`
  （[11-entry §6](11-entry.md) 的改动清单里加一行）。
- 鼠标：`ScrollbackMouse` 绑到 Scrollback，拖选即复制（框架已有）。

## 4. 线程

```
渲染线程（main）                      agent 线程（Shell 的 jthread）
  Runtime::run()                        loop: job = jobs.pop(); job(*agent)
  PromptInput: Enter ─jobs.push(run_turn)─►  agent.run_turn(input, sink, approver, stop)
  Esc ─ turn_stop.request_stop() ───────►     … Sink ─ rt.post(transcript.apply(e)) ─► 渲染线程
  ApprovalDialog ─ promise.set_value ◄──      Approver: post 打开对话框，等 future
```

### 4.1 Agent 的创建与归属

- `Shell` 在**进入全屏之前**创建 Agent（`create` 或 `resume`）：启动失败（模板错、会话找不到）时还能用普通 stderr
  报错退出。恢复时的 replay Sink 把事件先存进一个 `std::vector<Event>`，界面起来后在渲染线程上一次性交给
  Transcript。
- 创建之后 Agent **只在 agent 线程上用**（jthread 启动是同步点，交接是安全的）。

### 4.2 任务队列

```cpp
class JobQueue {                                   // mutex + condition_variable_any + deque
public:
    void push(std::function<void(agent::Agent&)>);
    std::optional<std::function<void(agent::Agent&)>> pop(std::stop_token);   // stop 时返回空
};
```

任务只有三种：`run_turn(input)`、`compact()`、`new_session()`（`/new`：在 agent 线程上销毁旧 Agent、创建新 Agent）。
实现中的队列封装在 `shell.cpp` 内，接收捕获所需输入的无参任务；关闭后丢弃尚未开始的任务。
Agent 的唯一跨线程操作是原子权限模式更新，`Shell` 在替换会话与切换模式时用同一把锁保护对象寿命。

### 4.3 每轮一个 stop_source

渲染线程提交 `run_turn` 时新建一个 `std::stop_source`，自己留一份（按 Esc 时 `request_stop()`），token 交给任务。
`stop_source` 的 `request_stop` 线程安全，不需要额外同步。

### 4.4 Sink

```cpp
agent::Sink sink = [&rt, &transcript](const agent::Event& e) {
    rt.post([&transcript, e] { transcript.apply(e); });     // 按值捕获一次
};
```

- 流式文本每个 delta 一次 `post` 就够了：Runtime 按 16 ms 合帧，不会因为 post 多而多出帧。
- `ToolOutput` 来自工具工作线程，`post` 本身线程安全。

### 4.5 Approver

```cpp
agent::Decision approve(const agent::Approval& a, std::stop_token stop) {       // agent 线程
    auto state = std::make_shared<Pending>();          // promise<Decision> + atomic<bool> done
    auto answer = [state](agent::Decision d) { if (!state->done.exchange(true)) state->promise.set_value(d); };
    rt.post([&, a, answer] { dialog.open(a, answer); });
    std::stop_callback on_stop(stop, [&] { answer({agent::Decision::Answer::deny}); });
    agent::Decision d = state->promise.get_future().get();
    if (stop.stop_requested()) rt.post([&] { dialog.close(); });
    return d;
}
```

- 回答只能生效一次（`done` 标志）：用户按键和 stop 可能同时发生。
- stop 时对话框由 agent 线程 post 关闭；用户回答时由对话框自己关闭。

## 5. 按键

| 按键 | 空闲时 | 忙时 |
| --- | --- | --- |
| Enter | 发送（空输入忽略；`/` 开头按斜杠命令处理） | 放进排队区，本轮结束后自动发送 |
| Shift+Enter / Alt+Enter | 换行 | 换行 |
| ↑（输入框为空） | — | 把排队的内容拿回输入框编辑 |
| Esc | — | 中断本轮（`request_stop`） |
| Ctrl+C | 输入框非空：清空；为空：提示「再按一次 Ctrl+C 退出」，1 秒内再按退出 | 中断本轮 |
| Shift+Tab | 切换权限模式 ask ↔ accept_edits（`Agent::set_permission_mode`，线程安全） | 同左 |
| Ctrl+O | 展开 / 折叠所有工具输出 | 同左 |
| PgUp / PgDn / 滚轮 / 拖选 | 框架已有 | 同左 |

- 快捷键用 `tui::Keymap` 注册成命令（`session.interrupt`、`permission.cycle`……），全局处理器是 Keymap；焦点处理器是
  `PromptInput`。
- `PromptInput` 先处理 Enter、换行、↑，其余事件交给内部的 `tui::InputBoxHandler`。Shift+Enter 需要终端支持 kitty
  键盘协议才能和 Enter 区分；不支持的终端用 Alt+Enter。

### 5.1 斜杠命令

| 命令 | 做什么 |
| --- | --- |
| `/compact` | agent 线程执行 `compact()`（[07-context](07-context.md)），可取消，更新上下文状态，完成后处理排队输入 |
| `/new` | 任务 `new_session()`，清空 Document，状态栏换会话 id |
| `/help` | 在对话里插一个块：按键表和命令表 |
| `/exit` | 退出 |

忙时输入的斜杠命令也进排队区，按顺序执行。不认识的命令：Notice「未知命令 /xxx」，不发给模型。

## 6. 对话的画法（Transcript）

### 6.1 块与标签

所有非 Markdown 的块用 `BlockKind::text`，靠 `meta` 标签区分，由 `ChatRenderer` 统一上色（通过
`Document::set_renderer(BlockKind::text, …)` 替换默认渲染器）：

| meta | 样式（ThemeTokens） | 前缀 |
| --- | --- | --- |
| `user` | `primary` | `› ` |
| `reasoning` | `text_muted` | `∴ ` |
| `tool` | 按状态：运行中 `accent`、成功 `success`、失败 `error`、中断 `text_muted` | `● ✓ ✗ ◌` |
| `info` | `text_muted` | 无 |
| `warn` / `error` | `warning` / `error` | 无 |

代码、diff、bash 输出用框架的 `code`、`diff`、`output` 块；assistant 正文用 `MarkdownStream`。

### 6.2 事件 → 块

| 事件 | 做什么 |
| --- | --- |
| `TurnStarted` | 追加 `user` 块（`margin_top = 1`）；Activity「思考中」；启动计时器（§7） |
| `StepStarted` | 记下 `step_first_block = 下一个块 id`；新建 `MarkdownStream(doc, 1)` |
| `ReasoningDelta` | 第一次时开一个 open 的 `reasoning` 块并折叠到 3 行；之后 `append` |
| `TextDelta` | `markdown.feed(text)` |
| `StreamReset` | `doc.erase_from(step_first_block)`；换一个新的 MarkdownStream |
| `ToolPending` | 只更新 Activity：「准备调用 edit…」 |
| `ToolStarted` | 先 `markdown.finish()`、关闭 reasoning 块；追加 `tool` 标题块（●）和一个空的**主体块**（按工具类型选 kind，见 §6.3），记 `call_id → {标题, 主体}` |
| `ToolOutput` | `append(主体, chunk)` |
| `ToolFinished` | 没有 ToolStarted 的（参数错、被拒、未执行）先补标题块；`replace(标题, 带状态的标题)`；按 View 填主体（§6.3）；关闭主体并按规则折叠 |
| `Retrying` | Notice（warn）：「连接中断，2 秒后重试（1/2）」 |
| `Compacted` | 追加 `info` 块：「上下文已压缩：180k → 90k tokens」 |
| `ContextUpdate` | 更新 StatusLine |
| `Notice` | info / warn 进 Notice 条；error 同时追加一个 `error` 块（留在对话里） |
| `TurnEnded` | `markdown.finish()`；按状态追加块：interrupted →「已中断」、denied →「已拒绝，等待你的指示」、limit →「达到本轮上限」、failed → error 块；Activity 置空；停计时器；有排队就发送 |

**为什么主体块在 ToolStarted 时就建好**：并行组的几个调用会先依次发 ToolStarted，再交错发 ToolOutput。主体块和标题块
成对、按顺序建好之后，`ToolOutput` 按 id 追加到各自的主体里，显示顺序始终和调用顺序一致；Document 只能在末尾追加块，
等第一个输出块到来再建就会乱序。空的 open 块不占行。

### 6.3 各工具的标题与主体

| View | 标题（完成后） | 主体 | 折叠 |
| --- | --- | --- | --- |
| `ReadView` | `读取 src/a.cpp 1–200 行` | 无 | — |
| `FileChangeView` | `编辑 src/a.cpp（+3 −1）` / `创建 src/b.cpp（42 行）` | `diff` 块，内容是 `diff` | 超过 20 行折叠到 20 |
| `BashView` | `$ make test`，后缀 `（退出码 1 · 3.2s）` / `（超时）` / `（已中断）`；非只读沙箱时加 `· 可写` / `· 联网` | `output` 块，实时追加；完成后用 `View::output` 替换（它是完整截断版） | 折叠到 10 行 |
| `GrepView` | `搜索 "foo"：12 处` | `code` 块，每行 `path:line: text` | 折叠到 5 行 |
| `GlobView` | `查找 src/**/*.hpp：8 个文件` | `code` 块，每行一个路径 | 折叠到 5 行 |
| `McpView` | `github.create_issue` | `text` 块：text 内容块拼接，其他类型写一行说明 | 折叠到 5 行 |
| `monostate`（prepare 失败等） | `summary` | `text` 块：`Result::text` 的前几行 | 折叠到 3 行 |

- 失败（`is_error`）的标题用 ✗；拒绝、未执行的用 ◌。
- 界面显示的内容和给模型的 `Result::text` 可以不同：界面用 View（更完整、有结构），模型用 text（有预算）。
- Ctrl+O 切换「全部展开」：遍历记录的主体块 `set_collapsed(false / true)`。

### 6.4 恢复会话

回放事件和实时事件走同一个 `Transcript::apply`，历史和实时画出来的完全一致（[01-events §3](01-events.md) 保证 6）。回放
不含 `ToolStarted`，所以 `ToolFinished` 自己补标题和主体。

## 7. 活动行与状态栏

**Activity**（忙时每 100 ms `tick` 一次，用 `Runtime::every`；空闲时取消计时器，保持静止零唤醒）：

| 当前状态 | 文本 |
| --- | --- |
| 等模型第一个 token | `思考中 12s` |
| 流式输出中 | `生成中 12s` |
| ToolPending | `准备调用 edit…` |
| 执行中的调用 | `运行 make test 3s`（取最早开始、还没结束的那个） |
| 等待权限回答 | `等待你的确认` |
| 压缩中 | `压缩上下文…` |

**StatusLine**：`deepseek-chat · 上下文 43%（107k/250k）· ask · MCP 2/3 · 01a0b514`

- 上下文来自 `ContextUpdate`；超过 trigger 用 warning 色。
- 权限模式 `accept_edits` 时用 accent 色显示「自动编辑」。
- MCP：`McpHub::states()` 线程安全，计时器顺带刷新；有 failed 时用 warning 色。

## 8. 权限对话框

```
┌ 修改文件 ───────────────────────────────────────────┐
│ 编辑 src/net/http.cpp（+3 −1）                       │
│ ┌─────────────────────────────────────────────────┐ │
│ │ @@ -120,7 +120,9 @@                              │ │  ← Scrollback + DiffRenderer，最高占屏幕 60%
│ │ -    curl_easy_setopt(h, CURLOPT_TIMEOUT, t);    │ │
│ │ +    if (t.count() > 0)                          │ │
│ └─────────────────────────────────────────────────┘ │
│ y 允许   a 本会话内修改工作区文件不再询问   n 拒绝   e 拒绝并说明 │
└─────────────────────────────────────────────────────┘
```

- 标题 = `Approval::reason`；第一行 = `intent.summary`；预览：write 用 `intent.preview`（diff），exec 用完整命令（`code` 块），
  read 列出路径，external 显示参数 JSON。
- 按键：`y` 允许；`a` 本会话允许（只在 `session_rule` 非空时出现，文字就是 `session_rule`）；`w` 允许并联网（只在
  `can_network` 时出现）；`n` / Esc 拒绝；`e` 在对话框底部出现一个 InputBox，Enter 提交说明（`deny_with_feedback`），
  Esc 退回。
- 对话框是模态的（`open_overlay(…, modal = &handler)`），打开期间输入框不接收按键；预览区可以用 PgUp/PgDn 滚动。
- 对话框打开时按 Ctrl+C：中断本轮（和 Esc 拒绝不同：Esc 只拒绝这一个调用）。

## 9. 退出

```
/exit、Ctrl+C 两次、SIGTERM：
    当前轮的 stop_source.request_stop()
    jobs 停止接收，worker 的 stop_token 请求停止
    Runtime::quit() → run() 返回 → Terminal 析构还原终端
    join agent 线程（本轮 1 秒内结束，见 04-turn §6）
    销毁 Agent（sync 会话记录、关闭 MCP）
    打印一行「会话 01a0b514 已保存，用 dagent -r 01a0b514 继续」
```

agent 线程的最外层 catch 未预期的异常：记日志，post 一个 error 块，然后 `Runtime::quit()`——不让界面卡在一个已经死掉的
agent 上。

`Interrupts` 由 main 传入。全屏期间（包括空闲和审批）启用 graceful；进程信号触发 stop 回调，
投递退出操作到渲染线程。`run()` 返回后先还原终端，再取消并 join 工作线程，最后析构 Agent 刷盘。
`/compact` 在 C5 之前只显示提示，MCP 状态等 C6 的 McpHub 接入后显示。
