小问题：install_signal_handlers 没有保存原来的信号处理器，卸载时直接设成 SIG_DFL，调用方自己装的处理器会被覆盖。

二、冗余或超范围的实现

可以直接删的：
- Attr::invalid、Style::invalid() 哨兵值，以及 & ~Attr::invalid 屏蔽。append_sgr 本来就把它当默认样式处理，而帧末的 \e[0m 已经保证每帧开始时终端处于默认状态。直接用 current = Style{} 完全等价，styled 这个标志也可以一起去掉。
- 从来没被读过：Surface::y0_。
- 没有任何地方调用：Rect::contains、Surface::repaint_all、Container::constraint()。
- Terminal::set_bracketed_paste：文档规定进入时按能力开启，不需要运行时开关。
- hline 里的行号检查是多余的，fill 已经会做区域求交。
- CMake 链接了 Threads::Threads，但 L1–3 里没有用到线程。

越过了 L3 的职责：
- Container 里的 focus_next、focus_prev、focus_index、on_event、cursor 属于 L6 的焦点链和路由。文档 §9.2 的设计是处理器栈，现在把焦点逻辑塞进容器，等于提前绑死了 L6 的实现方式。
- widget.hpp 里的 Key、Mods、Event 按文档 §十二 应该放在 input.hpp（L6），L1–3 阶段还用不到。

热路径上的重复工作：
- text() 已经算出了字素和宽度，却调用 put()，put() 又重新解码一遍。fill() 对每个格子也重复解码。两处都应该直接调用 write_cell，这样顺便就修好了 bug 5。
- build_bmp_table 里三段几乎一样的循环，可以合并成一个辅助函数。

结构上的气味：
- Container 通过 friend 直接改子控件的 rect_、dirty_、layout_dirty_。distribute 先赋一次 rect_，接着 layout(r) 又赋一次；layout_dirty_ 的清除也由外部代劳。更干净的做法是交给 Widget::layout 基类自己处理。
- layout.hpp 引用了 widget.hpp，也就是 L3 依赖 L4，违反了"依赖只向下"。这个矛盾在文档里就有（Container : Widget），建议要么把 L3 和 L4 合并成一层，要么把 Widget 基类挪到 L3。

注释和实际不符：
- Cell 注释写"约 15 字节 / 可整格 memcmp"：实际是 16 字节，里面有填充字节，代码也是用 operator== 比较的。
- present 头文件关于"整屏重绘"的说法不成立（见 bug 2）。
