# Agent 记忆效果评估报告

更新：2026-10-19。记录当前 `# Memory` 提示词（下称 v3）下的第一部分评估：MemoryCode 定量测试，覆盖 DeepSeek V4.1 Flash、Qwen3.8-27B、Nemotron 3.5 Bolt 74B-A9B、MiniCPM-V-4.7-35B-A3B 四个模型。第二部分（计划第 8 节的 9 个自定义场景）尚未开始。每个条件只运行一次，未排除运行间波动。

## 一 目标与方法

### 1.1 测试目标

检验 [记忆计划](../../nexttodo/memory-plan.md) 实现的全局与项目记忆，能否让 Agent 在后续会话中遵守用户在早先会话中给出的编码规范，并拆分失败原因：没有写入、写入后没有读取、读取后没有遵守。

### 1.2 数据集

[MemoryCode](https://github.com/for-ai/MemoryCode)（ACL 2025，Apache 2.0）：导师在多次会话中陆续给出编码规范，规范会被改写，会话中夹有闲聊和与代码无关的「伪规范」。最后一次会话附带若干编码问题，按每条规范**最新版本**的正则与 AST 判定是否遵守，判定不执行被测代码。

本次只取短历史：会话数为 2、5、10 的各 10 个，共 30 个历史（dialogue 31–40、121–130、151–160），170 次会话、116 个编码问题。

### 1.3 运行方式

每个历史的每次会话是一次独立的 `dagent run`，三种条件：

| 条件 | 会话喂入 | 探测 | 作用 |
| --- | --- | --- | --- |
| 关闭记忆 | 不喂入 | `memory.enabled=false`，直接提问 | 下限，规范只能靠猜 |
| 开启记忆 | 每次会话一个新 DAgent 会话，用户消息为「今天你和导师的对话记录」，由 Agent 自行决定是否写记忆 | 每个编码问题一个新会话 | 被测对象 |
| 完整历史 | 不喂入 | 关闭记忆，全部对话与问题放进同一提示词（论文 History 设置） | 参考上限 |

关闭记忆与开启记忆的探测语句相同：`Write a <问题>. Do not provide example usage.`，再加输出格式要求「只回复一个 Python 代码块，不创建或修改文件」。完整历史沿用论文提示词，末尾明确要求「遵守导师的全部最新规范」，因此它不是严格同条件的上限。

环境：

- 开启记忆的每个历史开始前清空记忆目录；每个运行的工作目录单独 `git init`，项目根即该目录，不加载 DAgent 仓库的 `AGENTS.md`；工作目录名为 `<公司名>-<模型>-<条件>-<编号>`，不含评测字样。
- 并行进程按服务端并发槽数设置（DeepSeek、Qwen3.8 为 4，MiniCPM 为 3，Nemotron 为 2），各用独立 Home：会话库、日志、记忆独立，配置与运行环境共享；只读沙箱可用。
- 权限为 workspace 模式，d3 决策模型（`d3-local`，`risk-first-v2-fixed-20261018`）照常审阅联网与工作区外读取。模型会用 web_search／web_fetch 查证规范中提到的依赖（如 `pedantic` 的装饰器）；headless 运行没有人工审批，转人工的请求不执行。memory 工具在所有模式下直接放行，不经过 d3。

### 1.4 评分与统计

- 得分：每个探测对最终规范逐条判定，取平均；历史得分为探测平均；总体为历史的宏平均。判定逻辑与 MemoryCode 原脚本一致。
- 写入统计：规范文本中引号内的关键词（如 `'_at'`、`'chx'`）出现在记忆快照中即视为已记下。
- 失败归类：对每条最新规范，未在所有探测中遵守时，按记忆快照分为「没记下来」「只有旧版本」「新旧并存」「记忆是最新的但探测没读」「读了记忆仍未遵守」。规范文本没有引号关键词（如「方法中加 assert」）时无法判断记忆内容，单列「无关键词」。

### 1.5 模型

| 配置名 | 模型 | 部署 |
| --- | --- | --- |
| `deepseek` | DeepSeek V4.1 Flash（`deepseek-flash`，默认思考） | DeepSeek 官方 API |
| `qwen38-local` | Qwen3.8-27B（W4A16，稠密） | 本机 RTX 3090，HyperQwen（vLLM，MTP 投机解码，fp8 KV），8 路并发 |
| `nemotron` | Nemotron-3.5-Bolt-74B-A9B（2 bit 量化，约 24 GB，MoE 约 9B 激活） | 远程 GB10，llama.cpp，1 路并发 |
| `local` | MiniCPM-V-4.7-35B-A3B（Q4_K_M，MoE 约 3B 激活） | 远程 GB10，llama.cpp，3 路并发 |

采样参数均为各服务默认值，未固定温度。

## 二 被测提示词

v3 的 `# Memory` 段对召回记忆的要求（实现见 [memory.cpp](../../src/private/tools/memory.cpp)，设计见 [memory](../design/memory.md)）：

- 用户希望遵守的规范与做法，不论记为 `user`、`feedback` 还是 `project`，都默认应用于其覆盖的全部代码和工作，包括独立的短代码片段，规范看起来不常见也照做。
- 只有用户明确要求与之相反的做法或 `AGENTS.md` 另有规定时才让步；请求中提到某个名字或只要求简短回答不算冲突。
- 文件路径、函数、配置、过往决策等召回事实是背景，使用前先核实。
- 写入准则另要求：用户陈述的规范按原样记录，不因无法核实而省略或改写。

Qwen3.8 完整历史分组：2 次会话 0.900、5 次会话 0.876、10 次会话 0.649。

## 四 分析

记忆机制本身（写入、索引注入、正文读取）在四个模型上都按设计工作；效果由模型对「何时写」「何时用」的判断决定，四个模型分别停在链路的不同环节：

- **MiniCPM：不写。** 170 次喂入会话只有 10 次调用工具，常回复「已记下」而不调用 memory；探测从不读取。开启与关闭记忆没有差别。
- **Nemotron：写一部分，但不看。** 约四成规范写入了记忆，索引也出现在探测的 system 中（如「方法名必须以 `_n` 结尾」），但 116 次探测只有 1 次调用工具，思考中完全没有提及记忆，22 条已写入的最新规范在探测中被忽略。所测为 2 bit 量化版本，长 system 下的指令遵循可能受量化影响，本次未单独验证。
- **Qwen3.8：写七成，用一部分。** 约三成规范没有写入，写入后仍有 20 条未遵守；喂入会话中常去探索空工作区。完整历史可达 0.814，开启记忆与之相差 0.32。
- **DeepSeek：基本完整。** 规范关键词几乎全部写入（107/111），可判断的失败只剩 7 条读后未遵守和 2 条未写入；开启记忆 0.859，与完整历史相差约 0.10，2 次会话的历史接近满分（0.975）。

在能用上记忆的两个模型中，5 次和 10 次会话的历史都低于 2 次会话。规范被多次改写时，模型需要更新旧条目、在探测中取用最新版本，这仍是主要难点；Qwen3.8 即使拿到完整历史，10 次会话也只有 0.649。

## 五 局限

- 每个条件只运行一次，采样温度未固定。
- MemoryCode 的规范为了可正则判定而刻意怪异，探测语句与空工作区带有评测痕迹，模型有时会因此犹豫是否应用规范；绝对分数不代表真实项目中的效果。
- 完整历史的提示词明确要求遵守全部最新规范，与开启记忆的探测不同条件，只作参考上限；Nemotron 未运行该条件。
- DeepSeek 的关闭记忆与完整历史、MiniCPM 的完整历史来自更早的运行，当时工作目录名含评测字样、独立 Home 的只读沙箱不可用（MiniCPM 当时使用真实 dev Home）；其余基线在本节环境下运行。
- 写入与失败归类基于关键词，无关键词的规范（14–47 条）未能归因；「新旧并存」含正确更新。
- 运行环境启用了联网与 d3 审阅，模型可查证依赖；不同环境（无网络、无 d3）下结果可能不同。
- Nemotron 与 MiniCPM 为远程 GB10 上的量化部署，结果反映该部署而非模型的完整精度版本。
